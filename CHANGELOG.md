# ALFA SMS — состояние системы и история изменений

> **Это источник правды для текущего поведения.** Если в коде и здесь расхождение —
> верь коду, но сначала прочти этот файл: многие «старые» правила уже изменены.
> Ветка разработки: `claude/telegram-miniapp-centralized-system-105bdk`.

## Текущие версии (на момент последней правки)
- **Приложение (APK): v2.11 = versionCode 12** — публикуется в OTA. Файл: `releases/alfa-sms-v2.11.apk`.
- **Сервер + мини-апп:** отметка сборки внизу мини-аппа **«сборка 2.13»**.
  Последние серверные изменения (2.12, 2.13) **APK не меняли** — только `git pull` + рестарт.

## Как выкатывать

**Сервер + мини-апп (git pull + рестарт):**
```bash
cd ~/parser-2.0
git fetch origin
git checkout claude/telegram-miniapp-centralized-system-105bdk
git pull --rebase origin claude/telegram-miniapp-centralized-system-105bdk   # если упадёт: git stash; pull; git stash pop
sudo systemctl restart alfa-sms
```
> `git pull` только обновляет файлы. Запущенный Node держит **старый** `server.js`
> в памяти — изменения сервера применяются **только после `systemctl restart`**.

**Публикация APK в OTA (только когда менялся APK):**
```bash
source .env
curl -u admin:$ADMIN_PASSWORD -X PUT --data-binary @releases/alfa-sms-v2.11.apk https://project.alfa-vpn.ru/admin/apk
curl -u admin:$ADMIN_PASSWORD -X POST -H "Content-Type: application/json" \
  -d '{"versionCode":12,"versionName":"2.11","notes":"Новая система мониторинга сигналов с большей конверсией"}' \
  https://project.alfa-vpn.ru/admin/release
curl -s https://project.alfa-vpn.ru/app/version.json    # ожидаем "versionCode":12
```
> OTA — **не тихое**: у пользователя на телефоне должно всплыть «Обновить», он
> подтверждает вручную. Пока не подтвердил — телефон живёт на старой логике.
> `versionCode` всегда должен только расти. Готовые APK лежат в `releases/`.

## ТЕКУЩЕЕ ПОВЕДЕНИЕ (источник правды)

### Режимы работы устройства
- **Немедленно** (`globalOn`, `workMode=manual`) — пользователь включил тумблер
  «Начать немедленную работу». Шлёт **пока пользователь не выключит** / не нажал
  «Снять все с работы». Приход «символ»/«успешно» **не останавливает** отправку;
  «символ» ведёт обычный цикл (пауза → «успешно» → следующий блок), а если все
  блоки пройдены — **стоп + отчёт**. Если «символ» не приходит — просто продолжает
  слать текущий блок, не останавливается.
- **Расписание** (`workMode=schedule`) — планировщик стартует токен в начале окна
  (промежутка). Останавливается, когда **окно закончилось**.
- **Сигнал** (`workMode=signal`) — стартует по «символу». **1 SMS на шаг**, затем
  только слушает 8464 до таймаута (**25 сек**). Пришёл «символ» → Ок → «успешно» →
  следующий блок (у него снова 1 проба). Нет «символа» за 25 сек → **стоп**.
  Максимум 1 SMS на шаг — сигнал больше не «льёт».

### Тумблер «Немедленно» отвязан от сигнала
`globalOn` может стоять `true` и из-за сигнала/расписания, но тумблер «Начать
немедленную работу» в мини-аппе теперь отражает **только ручной запуск**
(`manualOn = globalOn && workMode==='manual'`). Работа по сигналу/расписанию
показывается отдельной карточкой «📡 Идёт работа по сигналу» с кнопкой
«Остановить». Тумблер «Немедленно» гаснет **только когда его выключил
пользователь** — сигнал его больше не «мигает».

### Сигналы («символ» на 8464)
- **Любой пойманный «символ» = сигнал для всех** с включённым «Отработать по
  сигналу» (кроме тех, кто уже работает или у кого сейчас окно расписания).
- **«символ» от собственной работы НЕ считается новым сигналом.** Наружу сигнал
  рассылает только **простаивающее** устройство, поймавшее «символ» (обычно —
  проба из пула). Это разрывает петлю самоусиления.
- **Кулдаун на токен — 90 сек** (`SIGNAL_COOLDOWN_MS`): один токен не поднимается
  сигналом чаще, чем раз в 90 сек.
- **Глобальный дебаунс — 10 сек** (`SIGNAL_GLOBAL_DEBOUNCE_MS`): пачка «символов»
  при открытии окна (10–15 телефонов разом) = **один** запуск системы.
- **Авто-стоп сигнальной сессии на сервере — 2 мин** (`SIGNAL_SESSION_MAX_MS`):
  если устройство офлайн/на старом APK и не рапортует «готово», сервер сам гасит
  `globalOn`, чтобы залипшая «работа по сигналу» не блокировала новые сигналы.
- Источники «символа»: (а) внешний вебхук MacroDroid `/api/signal/<секрет>`;
  (б) отчёт устройства (`type:'signal'`) из приложения. **Оба НЕ зависят** от
  тумблера «Автопоиск сигнала» в админке.

### Пул автопоиска сигнала («Автопоиск сигнала» в админке)
- **По умолчанию выключен.** Тумблер в Админ-панели (`db.settings.probeEnabled`).
- Когда включён: **все активные устройства на связи** сами шлют пробные SMS
  (первый блок), **не более 3/час** каждое (`PROBES_PER_HOUR`), равномерно по
  времени, случайным выбором устройства. Пойманный «символ» на простаивающем
  устройстве → системный сигнал.
- Проба — это **реальная платёжная SMS** (первый блок устройства).

### Надёжность и стоп
- **Dead-man’s-switch (v2.10):** устройство шлёт **только пока связь свежая**.
  Нет успешного sync дольше ~35 сек → отправка сама останавливается и идёт
  переподключение. Так «выключил» срабатывает всегда: на связи — мгновенно, в
  офлайне — сам замолкает.
- **Работа в фоне:** приложение настойчиво требует отключить экономию батареи
  (диалог при каждом открытии, пока не выдадут) + кнопка «Работа в фоне».
- **Привязка не слетает** от разового 403 (нужно 4 подряд).
- **Массовые кнопки** на главной: «✅ Поставить все в работу» / «⛔ Снять все с
  работы» (`POST /api/mini/devices/active`).

### Платежи и отчёты
- «успешно» логируется на **каждое** «успешно» пока идёт сессия (даже если пауза
  на «символ» была пропущена) → дашборд «Платежи сегодня» и админ-сводка считают.
- Отчёт в бота содержит строку **«💸 Ушедших платежей: N шт. на СУММУ»** за сессию.
- **Плохой реквизит:** если «успешно» ни разу не пришло — реквизит не отрабатывает;
  при «операция отклонена» бот шлёт владельцу предупреждение заменить реквизит.

### Числа: платежи → **7878**; «символ»/«успешно» → с **8464** (туда «Ок»).

## Важные ENV (server/.env)
| Переменная | По умолчанию | Что делает |
|---|---|---|
| `SIGNAL_COOLDOWN_MS` | 90000 | мин. интервал перезапуска одного токена сигналом |
| `SIGNAL_GLOBAL_DEBOUNCE_MS` | 10000 | пачка «символов» = один запуск системы |
| `SIGNAL_SESSION_MAX_MS` | 120000 | авто-стоп залипшей сигнальной сессии |
| `PROBES_PER_HOUR` | 3 | лимит проб на устройство в час (пул) |
| `PROBE_MIN_GAP_MS` | 1500 | мин. пауза между пробами пула |

## История версий (кратко)
- **v2.2 / vc4** — фон: запрос отключения экономии батареи, BootReceiver, тип FGS
  dataSync; привязка не слетает от разового 403; быстрее восстановление связи.
- **v2.4 / vc5** — учёт «успешно» (лог + строка «Ушедших платежей» в отчёте),
  кулдаун сигнала 90с, «оплата не произведена» останавливает только сигнал;
  (в этой версии был circuit-breaker авто-стоп после 20 — **позже удалён**).
- **v2.5 / vc6** — **убран** circuit-breaker: «Немедленно» шлёт до выключения.
- **v2.6 / vc7** — авто-стоп убран везде, кроме сигнала; массовые кнопки вкл/выкл
  устройств; `POST /api/mini/devices/active`.
- **v2.7 / vc8** — пул автопоиска сигнала + тумблер в админке (по умолч. выкл).
- **v2.8 / vc9** — любой «символ» = сигнал для всех; настойчивый запрос батареи.
- **v2.9 / vc10** — все блоки пройдены → стоп + отчёт (без зацикливания).
- **v2.10 / vc11** — dead-man’s-switch: не слать по устаревшему `run` при потере
  связи → «выключил» всегда останавливает.
- **v2.11 / vc12** — сигнал = **1 SMS на шаг** + ожидание «символа» (таймаут 25с),
  иначе стоп; «символ» от собственной работы не считается новым сигналом.
- **сборка 2.12** (сервер+мини-апп, APK не менялся) — глобальный дебаунс сигнала
  10с; тумблер «Немедленно» отвязан от сигнала (`manualOn`/`workMode` в state,
  карточка «Идёт работа по сигналу»).
- **сборка 2.13** (сервер, APK не менялся) — авто-стоп залипшей сигнальной сессии
  на сервере (2 мин), чтобы старые/офлайн устройства не блокировали сигналы.

## Операционные заметки / диагностика

### «Устройство спамит само, не останавливается»
Почти всегда — **старый APK на этом телефоне** (до v2.11). В старой логике сигнал
после одного «символа» уходил в непрерывную отправку. Признак: `sentCount` намного
больше 3 в одной сигнальной сессии, «успешно» = 0.
**Что делать:** обновить приложение на этих телефонах (открыть → «Обновить» до
v2.11); заменить реквизит, если «успешно» ни разу не приходило; при необходимости
временно выключить у пользователя «Отработать по сигналу» и снять устройства с
активности (это остановит немедленно на устройствах, которые на связи).

### «Идёт работа по сигналу» висит и блокирует новые сигналы
Сигнальная сессия не завершилась (устройство офлайн/старый APK не рапортует
«готово»). На сервере сборки **2.13** это само гаснет за 2 мин (`SIGNAL_SESSION_MAX_MS`).
Если висит дольше — сервер не перезапущен после `git pull` (сделай `systemctl restart`).

### Проверка/диагностика
- Версия OTA: `curl -s https://project.alfa-vpn.ru/app/version.json`.
- Кэш мини-аппа: `curl -sI https://project.alfa-vpn.ru/ | grep -i cache-control` → `no-store`; внизу мини-аппа отметка сборки.
- Лог сигналов: `GET /api/admin/signals` — источник (`webhook`/`device:Имя`),
  какие токены стартовали, `debounced:true` для схлопнутых пачек.
- Сводка платежей: `GET /api/admin/payments`.
