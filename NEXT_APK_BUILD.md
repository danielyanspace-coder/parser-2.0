# Задача: собрать и опубликовать новый APK

> Этот файл — заготовленная задача для сборки следующей версии приложения.
> После выполнения обнови его под следующий релиз (или удали, если очередной
> задачи пока нет) — он не история, а разовое задание.

## Контекст

В ветке `claude/telegram-miniapp-centralized-system-105bdk` (коммит `f382c1f`,
«Report installed app versionCode from device to server; flag outdated devices
in admin») добавлена отправка версии приложения на сервер:
`ControlClient.kt` теперь кладёт `appVersionCode` (`BuildConfig.VERSION_CODE`)
в каждый статус-запрос, чтобы админ-панель мини-аппа могла увидеть, какие
устройства не обновились, и подсветить их.

Серверная и мини-апп часть уже задеплоены и работают. Но само изменение —
только в исходниках Kotlin: APK с этим кодом ещё не собирался (на сервере нет
Android SDK/gradle, собрать может только эта сессия).

## Что нужно сделать

1. `git pull` до актуального состояния ветки
   `claude/telegram-miniapp-centralized-system-105bdk` — должен быть минимум
   коммит `f382c1f`.
2. Собрать **release** APK со следующим номером версии:
   - `versionCode`: **13**
   - `versionName`: **2.12**
   ```bash
   ./gradlew assembleRelease -PversionCode=13 -PversionName=2.12
   ```
3. Переименовать/положить готовый файл в `releases/alfa-sms-v2.12.apk`.
4. Обновить `releases/README.md` — добавить строку в таблицу версий.
5. Обновить `CHANGELOG.md` — добавить запись в «Текущие версии» и в «Историю
   версий» с описанием: **v2.12 / vc13** — устройство сообщает серверу свою
   установленную версию (`appVersionCode`) при каждой синхронизации; админка
   помечает устройства, отставшие от актуальной OTA-версии.
6. Закоммитить и запушить всё в ту же ветку
   (`claude/telegram-miniapp-centralized-system-105bdk`).

## Важно

- Тот же ключ подписи (`app/alfa-release.jks`, пароль в `build.gradle.kts`),
  тот же `applicationId` (`com.checkout.alfasms`) — чтобы APK ставился поверх
  старой версии без удаления и без конфликта подписи.
- `versionCode` всегда должен только **расти** — не переиспользуй и не
  занижай номера.
- **Публикацию в OTA (загрузку `.apk` на сервер и вызов `/admin/apk` +
  `/admin/release`) делает другая (серверная) сессия** — здесь этого делать
  не нужно, только собрать APK и запушить его в репозиторий вместе с
  обновлёнными `releases/README.md` и `CHANGELOG.md`.
