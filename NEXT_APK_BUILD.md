# Задача: собрать и опубликовать новый APK

> Заготовленная задача для сборки следующей версии приложения. После
> выполнения обнови её под следующий релиз (или удали, если очередной
> задачи пока нет) — она не история, а разовое задание.

## Контекст

Последний собранный APK — **v2.12 = versionCode 13** (коммит `0d8fdde`).
С тех пор в ветке `claude/telegram-miniapp-centralized-system-105bdk`
накопилось три Android-затрагивающих коммита, ещё не попавших ни в один
APK:

1. **`1425c39`** — «Немедленно» (`workMode=manual`) больше никогда не
   завершает себя само по приходу «символ»/«успешно» — блок просто
   продолжает слать на интервале, пока пользователь не выключит вручную.
   (Серверная часть этого фикса уже задеплоена и работает независимо от
   APK; здесь — Android-половина того же фикса.)
2. **`ed16870`** — ручной ввод кода привязки (когда камера не работает),
   без сканирования QR.
3. **`3bfa8d5`** — «успешно» теперь принимается **и с гейтвея (7878), и с
   сигнального номера (8464)**, а не только с сигнального. Это был
   корень проблемы «в логах платежей всегда 0» — подтверждения с 7878
   просто молча игнорировались.

## Что нужно сделать

1. `git pull` до актуального состояния ветки
   `claude/telegram-miniapp-centralized-system-105bdk` — должен быть
   минимум коммит `3bfa8d5`.
2. Собрать **release** APK со следующим номером версии:
   - `versionCode`: **14**
   - `versionName`: **2.13**
   ```bash
   ./gradlew assembleRelease -PversionCode=14 -PversionName=2.13
   ```
3. Положить готовый файл в `releases/alfa-sms-v2.13.apk`.
4. Обновить `releases/README.md` — добавить строку в таблицу версий.
5. Обновить `CHANGELOG.md` — «Текущие версии» + «История версий»:
   **v2.13 / vc14** — «Немедленно» не завершается само; ручной ввод кода
   привязки; «успешно» принимается с гейтвея (7878) и сигнального (8464)
   номера — чинит логирование успешных платежей (было всегда 0).
6. Закоммитить и запушить всё в ту же ветку.

## Важно

- Тот же ключ подписи (`app/alfa-release.jks`), тот же `applicationId`
  (`com.checkout.alfasms`) — чтобы APK ставился поверх старой версии без
  удаления и без конфликта подписи.
- `versionCode` всегда должен только **расти**.
- **Публикацию в OTA (загрузку `.apk` на сервер и вызов `/admin/apk` +
  `/admin/release`) делает другая (серверная) сессия** — здесь этого
  делать не нужно, только собрать APK и запушить его в репозиторий
  вместе с обновлёнными `releases/README.md` и `CHANGELOG.md`.
